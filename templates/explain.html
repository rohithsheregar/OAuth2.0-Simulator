OAUTH 2.0 · INTRODUCTION

A safer way to grant application access

OAuth 2.0 is an authorization framework that lets a user give an application limited access to protected resources without sharing the user’s password with that application.

What OAuth 2.0 means

OAuth 2.0 separates authorization from password-based authentication. The user signs in with a trusted Authorization Server, reviews the permissions requested by an application, and grants only the access they approve.

The application then uses a time-limited access token to call a Resource Server. The token represents permission—it is not the user’s password and should be limited to the required scopes.

Why it is used

  • Applications do not need to collect or store user passwords.
  • Users can approve specific scopes instead of sharing everything.
  • Access can be time-limited, revoked, and separated by application.

Where it is used

  • “Sign in with …” experiences on web applications.
  • Mobile and desktop applications accessing online APIs.
  • Business integrations connecting one service to another.

The Authorization Code flow

1RedirectThe user is sent to the Authorization Server.
2ConsentThe user signs in and approves requested scopes.
3CodeA short-lived authorization code returns to the client.
4ExchangeThe server exchanges the code for an access token.
5AccessThe token is presented to the protected API.

Advantages

  • Password isolation between the user and third-party applications.
  • Fine-grained, scope-based permissions.
  • Short-lived and revocable credentials.
  • Works across browsers, mobile apps, APIs, and service integrations.

Limitations and risks

  • More moving parts than a simple username-and-password flow.
  • Incorrect redirect URI or state validation can create serious vulnerabilities.
  • Bearer tokens must be protected because whoever holds one may use it.
  • Production systems require HTTPS, secure storage, rotation, and careful token expiry.
Remember

OAuth 2.0 delegates access; it does not automatically prove identity. Use an established authentication protocol such as OpenID Connect when an application also needs a verified user identity.
